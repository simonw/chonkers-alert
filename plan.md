# Plan: Chonkers (Steller Sea Lion) sightings tracker

## Context

Chonkers, an enormous Steller sea lion, is currently hanging out at Pier 39 in
San Francisco and people are logging sightings on iNaturalist. We want a
public site for this repo (`simonw/chonkers-alert`) that:

1. Periodically scrapes recent Steller sea lion observations within a
   bounding box covering the SF waterfront from the iNaturalist API.
2. Commits the pretty-printed JSON to the repo (so the history shows new
   sightings as commits).
3. Publishes a webpage at the repo's GitHub Pages URL listing the most
   recent sightings — newest first, with photos and observer info.
4. Publishes an Atom feed alongside it so the user (and others) can
   subscribe and get pinged by their feed reader when Chonkers is spotted.

This iterates on the pattern in `simonw/recent-california-brown-pelicans`
(scrape → commit JSON → build feed → deploy via Pages), with the addition
of a build-time-rendered HTML page for the photos.

The reference repos are cloned at:
- `/tmp/recent-california-brown-pelicans` — primary template
- `/tmp/tools` — for HTML/CSS inspiration (esp. `inat-sightings.html`,
  `image-gallery-component.js`)

## Key design choices (confirmed with user)

- **Bounding box**: SF waterfront, Aquatic Park to Bay Bridge —
  `swlat=37.795, swlng=-122.420, nelat=37.815, nelng=-122.388`.
- **HTML rendering**: Python script generates static `index.html` at build
  time (parallel to `to_atom.py`) — fast load, no JS required, both
  artifacts built in one workflow step.
- **No map**: Just photo cards. Coords link out to Google Maps.

## Steller sea lion taxon ID

iNaturalist taxon ID for *Eumetopias jubatus* (Steller sea lion) is **41753**.
The script should verify this by hitting
`https://api.inaturalist.org/v1/taxa?q=Steller%20sea%20lion` once during
implementation, then hard-code the ID in `scrape.sh`.

## Files in detail

### `scrape.sh`

Single line, mirroring `/tmp/recent-california-brown-pelicans/scrape.sh:2`:

```bash
#!/bin/bash
./download.sh 'https://api.inaturalist.org/v1/observations?taxon_id=41753&swlat=37.795&swlng=-122.420&nelat=37.815&nelng=-122.388&per_page=200&order=desc&order_by=observed_on&term_id=17&without_term_value_id=19'
```

- `term_id=17&without_term_value_id=19` filters out "Dead" observations
  (term 17 is "Alive or Dead", value 19 is Dead) — keep, since we want live
  Chonkers sightings.
- `per_page=200` (max) — bounding box is small so this should comfortably
  fit all current results in one page.

### `download.sh`

Copy `/tmp/recent-california-brown-pelicans/download.sh` verbatim, with one
edit: extend the jq filter on line 84 to keep additional fields we need for
the HTML page:

```bash
jq '.results = (.results | map({id, time_observed_at, observed_on_details, observed_time_zone, observation_photos, geojson, place_guess, user: (.user | {login, name, icon_url}), uri, description}))'
```

Added: `user` (observer attribution on the page), `uri` (canonical iNat
link — though we already build it from `id`), `description` (if the
observer wrote notes), `observed_on_details` (handy for displaying date
when `time_observed_at` is null).

### `to_atom.py`

Copy `/tmp/recent-california-brown-pelicans/to_atom.py` and change:

### `to_html.py` (new)

Build a single static `index.html`. Stdlib only (`json`, `html`,
`datetime`, `sys`) — no jinja, no deps — to match the pelican-repo ethos.

Reads JSON from stdin or argv, writes HTML to stdout. Renders:

- Page header: "Chonkers Alert" / "Recent Steller sea lion sightings
  near Pier 39, San Francisco" / "Updated <UTC timestamp>".
- Link to the Atom feed (`atom.xml`) and to the source repo.
- Sightings sorted by `time_observed_at` descending. For each:
  - **Photo grid** — all `observation_photos`, transforming
    `square.jpg`→`medium.jpg` for the thumbnail and linking each `<a>`
    to the `large.jpg` so clicking opens the big version (no JS
    lightbox needed).
  - **Date** (formatted from `time_observed_at`, fall back to
    `observed_on_details.date`).
  - **Place** (`place_guess`).
  - **Observer**: `user.name` or `user.login`, with their avatar
    (`user.icon_url`) and a link to their iNat profile.
  - **Description** (if non-empty), HTML-escaped, with `\n`→`<br>`.
  - **Links**: "View on iNaturalist" (`https://www.inaturalist.org/observations/{id}`)
    and "Open in Google Maps" using the geojson coords.

CSS inline in `<style>`. Take cues from `/tmp/tools/inat-sightings.html`
(`.clump` card pattern) and `/tmp/tools/image-gallery-component.js`
(flex-wrap photo grid with consistent row height). Mobile-friendly with a
`max-width: 800px` container and `prefers-color-scheme: dark` support
(simonw's tools all do this).

## Verification

End-to-end check before pushing:

1. **Scrape locally** (requires `curl`, `jq`):

   ```bash
   chmod +x scrape.sh download.sh
   ./scrape.sh
   ls *.json   # should show one pretty-printed JSON file
   ```

   Spot-check the JSON: confirm it has a `results` array with at least
   a few entries (Chonkers is being widely observed right now, so the
   bbox should yield results) and that each result has `observation_photos`,
   `geojson`, `place_guess`, and `user`.

2. **Build the feed and page**:

   ```bash
   mkdir -p _site
   cat *.json | python3 to_atom.py > _site/atom.xml
   cat *.json | python3 to_html.py > _site/index.html
   ```

3. **Validate output**:
   - Open `_site/index.html` in a browser — most recent sighting on top,
     photos load, "View on iNaturalist" links resolve, Google Maps links
     open the right pin.
   - `xmllint --noout _site/atom.xml` parses cleanly.
   - Drop the feed URL into a feed validator (e.g. `validator.w3.org/feed`)
     once the page is live — or at least eyeball that entry IDs, updated
     timestamps, and `<link rel="enclosure">` photo links look right.

4. **Workflow rename**: After commit, the user renames `github/` →
   `.github/`. Then the schedule + Pages deploy take over.

5. **First Action run**: trigger via `workflow_dispatch` in the GitHub UI;
   confirm `_site/atom.xml` and `_site/index.html` get deployed and the
   Pages URL serves them.

## Out of scope

- Filtering by individual sea lion identity (no way to tell "Chonkers"
  vs. another Steller in the bbox from the API; the bbox is the proxy).
- Email/SMS alerts — the Atom feed is the alerting mechanism.
- Historical archive beyond what the bounded API call returns
  (`per_page=200` is plenty for the active sighting window).
